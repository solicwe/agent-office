# คู่มือใช้งาน Agent Office

Agent Office เป็นหน้าต่างแสดงการทำงานของ AI บนเครื่องคุณ พร้อมบันทึก audit log สำหรับเปิดดูและส่งออกรายงาน สั่งงานในโปรแกรม AI ตามปกติ แล้วเปิด Office ดูควบคู่กัน

- **Codex Desktop / CLI:** ดูการใช้เครื่องมือ รันคำสั่ง แก้ไฟล์ และจบงาน จากไฟล์ session ที่อยู่ในเครื่อง
- **Claude Code:** ดูงานและการมอบหมายให้ subagent ผ่าน hooks ของโปรเจกต์
- **ChatGPT / Gemini บนเว็บ:** นำเข้า log หลังคุยเสร็จ ยังไม่มีการแสดงสด

แต่ละคนใช้บัญชี AI ของตัวเอง ไม่ต้องใช้บัญชีหรือ API key ของเจ้าของ repository การ clone โค้ดไม่ได้เชื่อมกับ Codex ของผู้ส่ง ระบบเก็บ log ในเครื่องและปิดการ push hash เป็นค่าเริ่มต้น ส่วน AI ใช้โควตาหรือคิดค่าบริการตามบัญชีของคุณตามปกติ

## 1. เตรียมเครื่อง

ติดตั้งสิ่งต่อไปนี้:

1. Git สำหรับ clone และอัปเดตโปรเจกต์
2. Node.js **20 ขึ้นไป** ซึ่งมี npm มาด้วย
3. โปรแกรม AI ที่ต้องการใช้ และลงชื่อเข้าใช้บัญชีของคุณเอง

ตรวจสอบใน Terminal หรือ PowerShell:

```bash
git --version
node --version
npm --version
```

ต้องเชื่อมต่ออินเทอร์เน็ตเมื่อติดตั้ง dependency ครั้งแรก การติดตั้ง Agent Office ไม่ได้ติดตั้ง Codex หรือ Claude Code ให้

## 2. ดาวน์โหลดจาก Git

```bash
git clone https://github.com/solicwe/agent-office.git
cd agent-office
```

ถ้า repository จำกัดสิทธิ์ ให้เจ้าของเพิ่มสิทธิ์บัญชี Git ของคุณก่อน

โฟลเดอร์ `agent-office` ใช้เปิดโปรแกรม ส่วน **โฟลเดอร์งาน** คือโปรเจกต์ที่ต้องการให้ AI ช่วยทำ สองโฟลเดอร์นี้จะเป็นที่เดียวกันหรือคนละที่ก็ได้

## 3. ติดตั้งและตั้งค่าครั้งแรก

วิธีผ่าน Terminal ใช้ได้ทั้ง Mac, Windows และ Linux รันจากโฟลเดอร์ `agent-office`:

```bash
npm install
npm run setup
```

ตัวตั้งค่าจะถาม:

1. **ใช้ AI ตัวไหน:** พิมพ์ `1` สำหรับ Codex, `2` สำหรับ Claude Code หรือ `3` สำหรับแชทเว็บ กด Enter เปล่า ๆ จะเลือก Codex
2. **โฟลเดอร์โปรเจกต์:** สำหรับ Codex/Claude ให้ใส่ path แบบเต็มของโฟลเดอร์งานที่มีอยู่จริงบนเครื่องคุณ กด Enter เพื่อใช้โฟลเดอร์ Agent Office เอง

ตัวอย่าง path:

- Mac: `/Users/your-name/projects/my-app`
- Windows: `C:\Users\YourName\projects\my-app`
- Linux: `/home/your-name/projects/my-app`

ใส่ path จริง ไม่ใช่ URL GitHub และไม่ใช่ชื่อไฟล์ สำหรับ path ที่มีช่องว่าง ใส่ข้อความทั้ง path ได้ ตัวตั้งค่ารับเครื่องหมายคำพูดครอบได้ด้วย อย่าใส่ `~` แทน home directory ในช่องนี้ ให้ใช้ path เต็ม

เมื่อตั้งค่าเสร็จ โปรแกรมจะสร้าง `office.local.json` สำหรับเครื่องนี้ ไม่ต้องสร้างเอง และไฟล์นี้ถูกละเว้นจาก Git

ถ้าเลือก Claude Code กับโปรเจกต์อื่น ตัวตั้งค่าจะเพิ่ม roles และ hooks ในโปรเจกต์ที่เลือก รายละเอียดอยู่ในหัวข้อ Claude Code ด้านล่าง

## 4. เปิด Office

```bash
npm start
```

เปิดเบราว์เซอร์ที่ **http://localhost:3000** และเปิด Terminal ที่รันโปรแกรมค้างไว้

อีกวิธีคือใช้ไฟล์เปิดโปรแกรม:

- **Mac:** ดับเบิลคลิก `start.command` หรือรัน `bash start.command`
- **Windows:** ดับเบิลคลิก `start.bat`
- **Linux:** รัน `bash start.sh`

ไฟล์เปิดโปรแกรมจะติดตั้ง dependency ถ้ายังไม่มี และเรียกตัวตั้งค่าถ้ายังไม่มี `office.local.json` จากนั้นเปิดเบราว์เซอร์ให้ ส่วนการรัน `npm start` โดยตรงจะไม่ถามตั้งค่า จึงควรรัน `npm run setup` ก่อนในครั้งแรก

หยุดโปรแกรมด้วย **Ctrl+C** ใน Terminal แล้วเปิดใหม่เมื่อต้องการใช้

## 5. ใช้กับ Codex ของคุณ

1. เลือก Codex ใน `npm run setup` และระบุโฟลเดอร์งาน
2. เปิด Agent Office ก่อนส่งคำสั่งรอบใหม่
3. เปิดโฟลเดอร์งานเดียวกันใน Codex Desktop หรือเปิด Codex CLI จากโฟลเดอร์นั้น
4. สั่งงานตามปกติ เช่น:

   > สร้าง hello.html เป็นหน้าเว็บภาษาไทย มีช่องกรอกชื่อและปุ่มทักทาย

5. กลับมาดูแท็บ **สด** ใน Office จะเห็น Codex ใช้เครื่องมือและทำงานที่โต๊ะหลัก
6. ดูบันทึกในแท็บ **Audit log** โดยเลือก session ที่มีป้าย `[Codex สด]`

ไม่ต้องเพิ่ม hooks ของ Claude ให้ Codex และไม่ต้องคัดลอก `AGENTS.md` เพื่อเชื่อมภาพสด ไฟล์ `share/AGENTS.md` เป็นคำสั่งบทบาทเพิ่มเติมสำหรับทีม ไม่ใช่ตัวเชื่อม Office

### ขอบเขตการแสดงผล Codex

- อ่านเฉพาะ session ที่ `cwd` ตรงกับโฟลเดอร์งานที่เลือก ถ้าใช้ worktree ต้องเลือก path ของ worktree ที่ Codex ทำงานจริง
- อ่านไฟล์ใน `~/.codex/sessions` ตามค่าเริ่มต้น หรือจาก `CODEX_HOME/sessions` หากตั้ง `CODEX_HOME` ไว้
- ตรวจไฟล์ทุกประมาณ 1 วินาที เหตุการณ์ปรากฏหลัง Codex เขียนลงไฟล์แล้ว จึงอาจช้ากว่าหน้าจอ AI
- ข้ามประวัติเก่าเมื่อพบไฟล์ที่มีอยู่ตอนเปิดครั้งแรก เก็บตำแหน่งอ่านไว้ใน `logs/.codex-cursors.json` เพื่ออ่านต่อ
- ถ้าเปิด Office กลางงาน อาจไม่มีคำขอเริ่มต้นของรอบนั้น ให้ลองส่งงานรอบใหม่
- แสดง Codex เป็นผู้ช่วยหลัก และแสดง subagent ที่เรียกจริงจาก metadata ของ Codex พร้อมมอบหมายงาน ใช้เครื่องมือ และส่งงานกลับ โดยรวม audit ใต้ session หลัก ไม่แสดงจำนวนโทเค็นหรือ worker ตรวจ permission ภายใน
- ตั้งชื่อ task เป็น `pm`, `architect`, `backend`, `frontend`, `qa`, `debugger` หรือ `reviewer` เพื่อใช้โต๊ะตรงบทบาท ชื่ออื่นใช้ Helper ระบบไม่เดาบทบาทจากเนื้อหาคำสั่ง
- การแสดงภาพไม่ได้เป็นตัวเรียก agent ต้องให้ Codex เรียก subagent จริง และเปิด Office ค้างไว้ก่อนเริ่มงาน ข้อมูลก่อนเปิดจะไม่ถูกนำมาย้อนเล่น
- กรอง session ตรวจสิทธิ์ภายในออก รูปแบบไฟล์ session เป็นข้อมูลภายในของ Codex ซึ่งอาจเปลี่ยนหลังอัปเดต
- ใช้ได้กับ session ที่มีไฟล์อยู่บนเครื่องนี้ งานที่ทำบน cloud หรืออีกเครื่องและไม่มีไฟล์ในเครื่องนี้จะไม่ปรากฏ

## 6. ใช้กับ Claude Code ของคุณ

1. เลือก Claude Code ใน `npm run setup` และระบุโฟลเดอร์งาน
2. ถ้าเลือกโปรเจกต์อื่น ตัวตั้งค่าจะ:
   - คัดลอก roles ไปที่ `.claude/agents/` โดยไม่ทับ role เดิมของโปรเจกต์
   - เพิ่ม hooks ใน `.claude/settings.local.json` ให้ส่งเหตุการณ์มาที่ `http://127.0.0.1:3000/hooks`
   - เพิ่มรายการละเว้นใน `.git/info/exclude` สำหรับ Git repo ปกติ
3. เปิด Agent Office แล้วเริ่ม session ใหม่ใน Claude Code ภายในโฟลเดอร์งานนั้น
4. ตรวจและยอมรับ hooks ของโปรเจกต์เมื่อ Claude Code ถาม
5. พิมพ์ `/agents` เพื่อตรวจรายชื่อทีม แล้วลองสั่ง:

   > ให้ frontend สร้างหน้า hello แล้วให้ reviewer ตรวจโค้ด

Claude จะเลือก agent ตามงาน การแก้เล็กน้อยอาจทำเองโดยไม่มอบงานให้ทุกคน เป็นพฤติกรรมปกติ

ถ้าใช้โฟลเดอร์ Agent Office เป็นโฟลเดอร์งาน จะมี roles และ hooks อยู่แล้ว ไม่ต้อง attach ซ้ำ

ในโฟลเดอร์ที่ไม่มี Git หรือเป็น Git worktree/submodule ตัวติดตั้งอาจเพิ่มรายการละเว้นให้ไม่ได้ ให้ตรวจไฟล์ `.claude` ก่อน commit ดูคู่มือทีมเพิ่มเติมที่ [TEAM_GUIDE.md](../TEAM_GUIDE.md)

## 7. ใช้กับ ChatGPT หรือ Gemini บนเว็บ

1. เลือกแชทเว็บใน `npm run setup` แล้วเปิด Office
2. เปิด [share/TEAM_PROMPT.md](../share/TEAM_PROMPT.md) และคัดลอกเนื้อหาไปเป็นคำสั่งเริ่มต้นในแชท AI ของคุณ
3. สั่งงานตามปกติ คำตอบควรมีบล็อกโค้ด `team-log` ที่มีข้อมูล JSON อยู่ท้ายคำตอบ
4. คัดลอกบทสนทนารวมบล็อกนั้น หรือบันทึกเป็นไฟล์ `.txt` / `.md`
5. ใน Office ไปที่ **Audit log → นำเข้า log จากแชท** ใส่ชื่อและแหล่งที่มา วางข้อความหรือเลือกไฟล์ แล้วกดนำเข้า

วิธีนี้เป็นข้อมูลที่ **AI รายงานเอง** ไม่ใช่การจับการใช้เครื่องมือจริง และไม่ได้ทำให้ตัวละครแสดงงานสด หากไม่พบบล็อก ให้ขอ AI ว่า “สรุปงานพร้อม team-log ตามรูปแบบที่ให้ไว้ด้วย”

## 8. อ่านและส่งออก log

- **สด:** แสดงเหตุการณ์และตัวละคร หากมีหลาย session ใช้ช่องเลือกด้านบนเพื่อเลือกงานที่จะดู
- **Audit log:** เลือก session กดโหลดใหม่หากข้อมูลยังไม่อัปเดต ดูคำสั่งและผลลัพธ์ พร้อมสถานะตรวจ hash chain
- **Export .json:** เก็บข้อมูลสำหรับตรวจสอบด้วยโปรแกรม
- **Export .md:** เก็บรายงานสำหรับอ่านหรือส่งต่อ
- **Roles:** ดูคำสั่งของสมาชิกทีมและข้อผิดพลาดของไฟล์ role รายการนี้ไม่ได้แปลว่า Codex เรียกใช้ทุก role จริง

ตัวอย่างตรวจไฟล์ JSON ที่ส่งออก จากโฟลเดอร์ Agent Office:

```bash
npm run verify -- "/path/to/audit-session.json"
```

ค่าเริ่มต้นไม่ยึด hash ลง Git จึงตรวจ hash chain ภายใน log ได้ แต่ไม่มีหลักฐาน anchor ภายนอก คำสั่ง `verify` จะรายงาน `[FAIL] ไม่พบ hash` และจบด้วย exit code 1 ในกรณีนี้ แม้ chain จะถูกต้อง นี่ไม่ได้แปลว่า log ถูกแก้ไข ให้ดูผลตรวจ chain แยกจากผล anchor หรือดูสถานะ chain ในหน้าเว็บ Hash chain ไม่ได้รับรองว่าเนื้อหาทั้งหมดเป็นความจริง หากต้องการยึด hash ให้ดูหัวข้อ audit ใน [TEAM_GUIDE.md](../TEAM_GUIDE.md) และใช้ remote/สิทธิ์ push ของคุณเอง

## 9. เปลี่ยน AI หรือโฟลเดอร์งาน

หยุด Office ก่อนด้วย Ctrl+C จากนั้นรันจากโฟลเดอร์ Agent Office:

```bash
npm run setup
npm start
```

ถ้าเคยติดตั้ง hooks ให้โปรเจกต์ Claude เดิม การเปลี่ยนค่าจะไม่ถอน hooks เดิมให้อัตโนมัติ หากเลิกใช้โปรเจกต์นั้นให้รัน:

```bash
npm run detach -- "/absolute/path/to/old-project"
```

คำสั่ง detach ใช้สำหรับไฟล์ที่เคยติดตั้งด้วย attach/setup เท่านั้น และจะเก็บ role ที่คุณแก้ไขเองไว้ให้

## 10. อัปเดตจาก Git

หยุด Office ก่อน แล้วรันในโฟลเดอร์ Agent Office:

```bash
git pull
npm install
npm start
```

ค่าเฉพาะเครื่องและ log ถูกละเว้นจาก Git ตามค่าเริ่มต้น หาก `git pull` แจ้งว่ามีไฟล์โค้ดที่แก้ค้างอยู่ ให้จัดการหรือบันทึกงานนั้นก่อน ไม่ต้องลบ log เพื่ออัปเดต

## 11. ปัญหาที่พบบ่อย

### เปิดเว็บไม่ได้ หรือขึ้น EADDRINUSE

ตรวจว่า `npm start` ยังทำงานอยู่และไม่มี error ถ้าพอร์ต 3000 ถูกใช้แล้ว ให้ปิด Agent Office ตัวเก่าก่อน การเปลี่ยนพอร์ตสำหรับ Claude ต้องแก้ URL hooks ให้ตรงด้วย ตัว setup ปัจจุบันตั้ง hooks เป็นพอร์ต 3000

### เปิด Office แล้วตัวละครยังไม่ขยับ

Office ไม่เรียก AI เอง ให้เปิด AI ที่เลือกและส่งคำสั่งรอบใหม่ ตรวจว่าโฟลเดอร์งานตรงกับที่ตั้งไว้ และช่อง session บนเว็บไม่ได้เลือก session เก่าค้างอยู่

### Codex ไม่ปรากฏ

เปิด **http://localhost:3000/api/codex**:

- `enabled: false`: อาจเลือก AI ตัวอื่นไว้ ให้รัน setup ใหม่เลือก Codex และตรวจว่าไม่ได้ตั้ง `CODEX_WATCH=off`
- `files: 0`: ยังไม่พบไฟล์ session ที่ตรงกับโฟลเดอร์งาน ให้ตรวจ path/worktree และลองเริ่มแชทในโฟลเดอร์นั้น
- `error` มีข้อความ: ตรวจสิทธิ์อ่านไฟล์หรือข้อความผิดพลาดนั้น
- `error: null`: ตัวอ่านยังไม่พบข้อผิดพลาด ไม่ได้รับรองว่ารูปแบบเหตุการณ์ทุกชนิดรองรับแล้ว

ถ้า Codex เก็บ session ในที่อื่น สามารถกำหนดก่อนเปิด Office เช่นบน Mac/Linux:

```bash
CODEX_SESSIONS_DIR=/absolute/path/to/sessions npm start
```

บน Windows PowerShell:

```powershell
$env:CODEX_SESSIONS_DIR = "C:\path\to\sessions"
npm start
```

Environment variables มีลำดับความสำคัญสูงกว่า `office.local.json` หากผลไม่ตรงกับที่ setup ไว้ ให้ตรวจค่าที่เคยตั้งใน Terminal ด้วย

### Claude ไม่มีเหตุการณ์

เริ่ม session ใหม่ในโฟลเดอร์งาน ตรวจว่าอนุญาต hooks แล้ว และ URL ใน `.claude/settings.local.json` ชี้มาที่ Office ที่เปิดอยู่ ถ้าใช้โฟลเดอร์ Agent Office เอง ให้ตรวจ `.claude/settings.json`

### นำเข้า log ไม่ได้

คัดลอกบล็อก `team-log` ให้ครบ รวมเครื่องหมายเปิดและปิดบล็อก JSON ต้องอ่านได้จริง ข้อความสรุปธรรมดาที่ไม่มีบล็อกนี้นำเข้าไม่ได้

### อ่าน office.local.json ไม่สำเร็จ

ไฟล์ตั้งค่าอาจเป็น JSON ที่ไม่ถูกต้อง หยุด Office เปลี่ยนชื่อไฟล์เดิมเพื่อเก็บสำรอง แล้วรัน `npm run setup` ใหม่ อย่านำไฟล์ตั้งค่าของเพื่อนมาทับ เพราะมี path ของเครื่องนั้น

### Windows รัน npm ใน PowerShell ไม่ได้

หาก PowerShell ปฏิเสธ `npm.ps1` ให้ใช้ Command Prompt หรือรัน `npm.cmd install`, `npm.cmd run setup` และ `npm.cmd start` แทน โดยไม่ต้องเปลี่ยนนโยบายระบบเพื่อใช้งานนี้

## 12. ข้อมูลอะไรอยู่ที่ไหน

- `office.local.json`: AI และโฟลเดอร์งานของเครื่องนี้
- `logs/`: ประวัติการทำงานและตำแหน่งอ่านไฟล์ Codex อาจมีคำสั่ง ข้อความ หรือรายละเอียดงานส่วนตัว
- `.claude/agents/`: คำสั่งของ roles ที่แชร์ผ่าน Git ได้
- `.claude/settings.local.json` ในโปรเจกต์ที่ attach: hooks และค่าเฉพาะเครื่องของ Claude

`logs/`, `office.local.json`, `.env`, `node_modules/` และ `dist/` ถูกละเว้นใน `.gitignore` ของ Agent Office อย่าใช้ `git add -f` เพื่อนำข้อมูลเหล่านี้ขึ้น Git โดยไม่ตรวจเนื้อหาก่อน

Office เปิดรับบน `127.0.0.1` เป็นค่าเริ่มต้น `localhost` ของเพื่อนหมายถึงเครื่องเพื่อน การ clone โค้ดไม่ได้เปิดให้คนอื่นอ่าน log ในเครื่องคุณ และไม่ได้ส่งต่อสิทธิ์บัญชี AI
